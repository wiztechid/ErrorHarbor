## Reader-first article standard

Every core page should normally contain:

1. exact error in H1
2. concise error fingerprint
3. environment/version context
4. Quick Fix above the fold
5. safest fixes first
6. expected output / verification
7. diagnostic decision flow
8. “Still not fixed?” branch
9. related errors
10. community area

No ad or affiliate promotion should block the first useful fix.

## Engagement

Each meaningful fix may ask:

- Yes, fixed
- No, continue

When enough real data exists, ErrorHarbor can calculate:

`Solved Rate = Yes responses / Valid feedback responses`

Never fabricate solved rates.

Comments are research data, not SEO decoration. Useful comments can reveal:

- existing-fix confirmation
- new environment/version
- new root cause
- new keyword/article opportunity

Community advice must not automatically be labeled verified.

## Affiliate rules

Affiliate recommendations are contextual only.

Preferred location:
- after the user has already received troubleshooting value
- maximum roughly 1 block for short/medium pages, up to 2 for long pages
- visually separated from technical instructions

Use a clear disclosure and `rel="sponsored"`.

A high payout never overrides relevance or reader trust.

## Monetization quality rule

> **Maximize Revenue Density without materially reducing Solved Rate, trust or problem-resolution speed.**

## Non-negotiables

1. SERP weakness before CPC excitement.
2. Reader success outranks empty engagement.
3. Topical fit is mandatory.
4. One canonical page beats cannibalization.
5. Cluster authority beats random keyword chasing.
6. Verification is mandatory.
7. Never fabricate tests, solved rates or community proof.
8. Never mass-publish templated AI troubleshooting pages.
9. Ads must not obstruct the fix.
10. Scale clusters that combine ranking, revenue and user success.
