VMware Operating System Not Found: Check Disk, Boot Order & Firmware

Fix VMware “Operating System Not Found” by checking the virtual disk, boot order, ISO/installation media, and BIOS/UEFI firmware match before changing advanced settings.

⚡ Quick Fix — check the virtual hard disk first

Power off the VM, open its settings, and confirm the virtual hard disk is present, connected, and configured to connect at power on.

VM Settings → Hard Disk → Connected ✓

Verify: Start the VM again. If it reaches the operating-system loader, the disk connection was the cause.

Why this happens

VM firmware shows this message when it cannot find a bootable system. Common causes include a disconnected virtual disk, an empty disk, an unexpected boot order, or a firmware mode that does not match the installed operating system.

Diagnose before changing more

1
Is the virtual disk listed in VM settings?
If it is missing, stop here and identify the correct virtual disk before changing firmware settings.
2
Did this VM boot successfully before?
A previously working VM makes a connection or boot-path change more likely than a missing OS installation.
3
Is this a new VM?
Confirm that an operating system has actually been installed, or that installation media is mounted for the first boot.
4
Did the error start after adding or removing a virtual NIC?
Broadcom documents ESXi cases where a NIC hardware change alters the remembered BIOS boot device and the VM falls through to PXE. Re-check the boot order before touching the disk.

Fix #2 — check the boot device and firmware path

If the virtual disk is attached, open the VM boot or firmware options and confirm the disk is available as a boot device. Also confirm that the VM firmware still matches the disk's boot layout: Broadcom documents current ESXi cases where switching a Windows VM between EFI/GPT and BIOS/MBR makes the VM fail with “Operating System not found” or “No bootable device.” Avoid changing firmware by trial and error.

🟡 Before changing configuration: note the current setting so it is easy to reverse.

Verify: Restart the VM. Success means the expected OS loader appears and the VM no longer falls through to PXE or an “Operating System Not Found” message.

What not to do

Do not switch BIOS ↔ UEFI by trial and error; firmware must match the disk/OS boot layout.Do not attach a random VMDK just because the VM powers on; confirm it is the disk that contains the operating system.Do not edit advanced VMX boot parameters before checking the attached disk and normal boot settings.

Still seeing the error?

If the disk is present and the boot order is reasonable, verify that the disk actually contains a bootable installation and that the VM firmware mode matches the way that operating system was installed.

Before escalating, capture:the exact console message or screenshotVMware product/version and host OSwhether this VM booted successfully beforethe virtual-disk filename(s) attached to the VMcurrent firmware mode and any recent hardware/boot changes
