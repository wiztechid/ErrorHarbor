Message Not Sent: Service Not Activated on Network

If Android shows “Message not sent: service not activated on network”, first find out what kind of message is failing. If ordinary SMS works but photos or group messages fail, troubleshoot the MMS/mobile-data path before resetting the phone. Google’s current guidance for MMS specifically starts with a data connection and resetting APN settings to default.

Plain SMS also failsCheck signal, active SIM/line, plan/credit and carrier activation before focusing on MMS settings.

🔎 Quick Check — is this specifically an MMS failure?

Send one short plain-text message to a known working number. Then send one photo to the same number. If text succeeds but the photo fails with this error, keep the diagnosis on MMS/mobile data/APN rather than resetting the entire phone.

Verify: Record whether plain SMS, photo MMS and group messaging succeed or fail separately. That result determines the next branch.

Diagnose the transport before changing settings

Use the result of the quick check to identify the failing transport. If plain SMS works but a photo or group message fails, the strongest first branch is MMS/mobile data/APN. If SMS also fails, move first to SIM, signal, line activation and carrier support. If only RCS fails, keep that separate from carrier SMS/MMS.

Verify: You should be able to state one precise failure pattern—SMS, MMS, RCS, one contact, or all messaging—before changing any network setting.

Fix path #1 — prove mobile data is working

Google’s current Messages troubleshooting says MMS requires a data connection. Android Help also recommends checking mobile data and switching between Wi-Fi and cellular data when diagnosing connectivity.

Temporarily turn Wi-Fi off, confirm mobile data is enabled, and load a normal webpage over cellular data. This is a diagnostic test—not a claim that Wi-Fi itself causes the error.

Verify: Cellular data should load a webpage. If it cannot, solve the mobile-data/line problem before treating this as a Messages-only failure.

Fix path #2 — reset APN settings to the carrier defaults

Google explicitly recommends resetting APN settings to default for MMS failures. APN values are carrier-specific, so avoid copying random APN values from forums. If your carrier publishes APN settings, compare against that carrier’s current instructions.

For example, T-Mobile’s current BYOD documentation includes an MMS-capable APN type and tells users to test data and/or MMS after saving the supported configuration. Other carriers can use different values.

Verify: After restoring the carrier-supported APN, restart if your carrier instructs it, then test one photo message again. Do not change multiple unrelated settings at the same time.

Fix path #3 — check SIM, line activation and messaging support

Google’s Messages guidance says to verify the SIM is inserted properly, the carrier supports SMS/MMS/RCS, the account has sufficient plan or credit, the phone has signal, and airplane mode is off. If both SMS and MMS fail, these checks move ahead of app-specific troubleshooting.

If you recently ported the number, replaced the SIM, activated an eSIM, changed plans or restored service, ask the carrier to verify that the line is fully activated and that SMS/MMS provisioning is enabled. Android Help directs activation and cellular-service problems to the mobile carrier.

Verify: Ask for a concrete test: can the line send a plain SMS and an MMS after provisioning is confirmed? Record which one still fails.

Fix path #4 — separate RCS from SMS/MMS

Google Messages can use RCS chats in addition to carrier SMS/MMS. If RCS is unavailable, that does not automatically mean MMS is unavailable; likewise, a working RCS conversation does not prove the carrier MMS path is correct.

If you recently changed messaging apps or phones, follow Google’s current Messages guidance for RCS/chat transitions rather than repeatedly toggling unrelated network settings.

Verify: Test a plain SMS and photo/group MMS independently of the RCS indicator. Continue with the transport that actually fails.

Fix path #5 — if only Google Messages fails

If the same SIM and carrier can send MMS from another supported messaging app but Google Messages alone fails, the evidence shifts toward the app/configuration layer. First update Google Messages and confirm it is the default texting app, both steps included in Google’s official troubleshooting.

Do not clear all phone data as an early experiment. Preserve the simpler comparison—same line, same APN, different app—because it is useful evidence if you need to report the issue.

Verify: Re-test the same recipient and same small attachment after updating/default-app checks. If only one app still fails, document the app version and send feedback through that app’s support path.

If only one contact fails

Google recommends checking that the contact is not blocked, the number is correct, and the required country code is present. A single-contact failure is weak evidence for resetting APN or carrier provisioning.

Verify: Send a plain SMS to another known working number. If other recipients work, stay on the contact/number branch.

What not to do first

Do not factory-reset the phone before separating SMS, MMS and RCS failures.Do not copy APN values from an unrelated carrier or an old forum post.Do not assume good Wi-Fi proves the cellular MMS path is healthy.Do not delete the eSIM or discard the SIM before the carrier verifies line provisioning.Do not change APN, app data, SIM and network settings simultaneously—you lose the evidence showing which change mattered.
